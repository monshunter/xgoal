## 当前事实与实施注意

以下内容细化 Plan 已有合同、失败保护和验收范围，不要求另建 Plan 或追加流程制品。

1. `Initialize` 当前只检查命名分支，不要求 `HEAD` 存在；`ensureOnlyInitPathsDirty` 已允许三个初始化路径和 `.xgoal/`，拒绝其他 dirty 文件。因此保持原有无关 dirty 拒绝是本次最小修复的有效边界，测试必须覆盖已暂存业务内容仍被拒绝且不发生提交。
2. 初始化会保留现有合法 `xgoal.yaml`、`.xgoalignore`，并向 `.gitignore` 补 `.xgoal/`。合同需写明这三个文件已有内容是否随首次提交纳入；不得仅凭文件名把运行目录、其他路径或用户业务修改一起提交。
3. 新仓库判定应验证命名分支确实尚无提交，其他 `HEAD` 解析错误须可诊断失败。已有提交仓库、重复 init 和失败后重跑应分别验证，不能因为解析失败而默认创建新根提交。
4. Git 身份、hooks/签名策略、文件写入或提交失败的恢复语义属于 1.1/2.2；应保留用户文件，明确实际暂存区变化及重跑条件。若使用显式三路径提交，应核对实际提交 Tree、父提交数量、HEAD 和 index，不能仅断言命令返回零。
5. 3.1 的证据必须证明真实 CLI/daemon 在新仓库初始化后越过原先 `HEAD` 读取失败并进入规划调用，同时记录提交文件范围与重复初始化结果。该验收边界是本次初始化修复，不得将它描述为游戏已开发或最终目标已验收。
