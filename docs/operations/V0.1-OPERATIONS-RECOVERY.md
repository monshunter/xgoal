# xgoal v0.1 操作与恢复手册

## 启动前检查

只在可信本地 Git 主工作目录或其子目录运行，linked worktree 入口不受支持。首次 Goal 前提交配置与已有修改，保持干净基线。以下示例从主工作目录执行（`config validate --file` 按显式文件路径读取）：

```bash
xgoal init
xgoal config validate --file xgoal.yaml
xgoal doctor
xgoal daemon start
xgoal daemon status
```

`doctor` 默认离线检查版本、配置、Git 和 daemon 可用性，不打开或迁移状态库，不构造执行 Adapter，不发起模型回合。主动探测必须显式指定 Profile 和正超时边界：

```bash
xgoal doctor --active --profile <id> --timeout 30s
```

## 项目定位与后台生命周期

每个 canonical Git Common Directory 只有一个 owner；主工作目录、子目录与 symlink 别名复用项目身份。独立 clone 独立。`--project`、`--state-dir`、`--socket` 优先于对应环境变量；未覆盖时遵循 Git common config 的状态绑定。绑定冲突或多个旧历史库时停止诊断，禁止另起空库掩盖数据。

默认状态为主目录 `.xgoal`，socket 使用用户私有短 runtime 路径以避免深仓库路径超出 Unix socket 限制。不要把 runtime 路径当作状态库或手工删除锁文件。后台日志保存在该 runtime 目录的 `daemon.log`，`daemon status` 显示实际定位和实例身份。

`daemon start --timeout 30s` 等待真实 readiness；同时启动只有一个 owner。`daemon stop --timeout 30s` 只停止身份匹配的当前实例，完成请求、执行、DB 关闭后释放锁；超时会明确报错，不强杀未知 PID。`daemon serve` 可前台运行，接受 SIGINT/SIGTERM。崩溃后可再次 `start`，不得按 socket 文件存在与否判断服务状态。

每项目独立进程不能限制跨项目资源竞争。项目服务使用项目作用域的名称和可配置端口；Provider 登录态、配额、主机资源及外部服务仍可能共享。

## 正常运行

`run` 返回的是已接收/已规划状态，不等于完成。用 `status --watch` 观察；退出码 `3` 表示 Waiting，`4` 表示 Cancelled。Gate 批准必须使用当前 Version、具体理由和一次性 Scope。Final Report 只有在 Required Work、最终 Validator、Finding、Gate、Evidence、Policy 和可选 Human Acceptance 全部成立后生成。

## 恢复顺序

Daemon 重启时在监听 Socket 前执行以下恢复：

1. 只读定位并按仓库锁、兼容状态锁的固定顺序取得所有权，检查 Git/DB 项目绑定；随后才打开 SQLite、检查 Migration Hash/版本、备份、WAL/PRAGMA 与权限；
2. 对未终态 Worker 核对 PID/PGID、启动身份和 Lease Generation；匹配时终止回收，不匹配时标记 Lost，不向未知进程发信号；
3. 将旧 worktree 执行标记为迁移等待；保留历史文件、报告与未决晋升日志，只有存在已终止进程观测的旧 Lease 才退出执行所有权；未知进程仍阻止新执行；
4. 恢复 `PENDING_RENAME` Final Report；匹配临时/最终文件则幂等确认，缺失时从 DB canonical payload 重建，不匹配时 fail closed；
5. 处理当前目录的未完成 Promotion，核对原 HEAD/index、当前 candidate Tree、Marker、Commit Trailer 与私有 Integration Ref；读回失败保留未决日志和所有权并等待，读回成功关闭对应恢复 Gate；
6. 重读 runnable Goal，只有当前 SQLite 状态允许时继续。

`resume` 不重建 Goal；`retry` 创建新 Attempt；`replan` 创建新 Plan Revision 并保留旧历史。原始失败、事件、Finding、Gate 和报告不会被静默覆盖。

## 故障处理

- `WAITING`：读取 `xgoal gates <goal-id>`、失败 Fingerprint 与推荐；修复外部条件或做有界授权后再 `resume`。
- `AGENT_UNAVAILABLE/INVALID_OUTPUT/TIMEOUT`：先检查 `doctor` 与 `logs`；相同 Fingerprint 无进展不会机械重试。
- `SCOPE_VIOLATION`：Attempt 进入 Quarantine；不要扩大范围，除非用户明确批准新的准确 Scope。
- `VALIDATOR_FAILED/UNAVAILABLE`：按实际 argv/Receipt 修复或恢复定义；不得从 Agent 输出替换 Required Validator。
- `CHECKOUT_WAITING` / `PATCH_CONFLICT`：保留当前文件与 Bundle，检查是否有外部源码、HEAD、index 或配置变化；不自动覆盖或接管未知修改。
- `checkout_retry_required`：检查保留的同一 Work 现场，使用当前 Work Version 显式 `work retry`；现场必须与已观察 Tree 和原身份完全一致。
- `promotion_recovery_required`：先恢复记录的 candidate Tree 与原 HEAD/index，再 resume 或重启以读回。私有 ref 已更新时不另建 Attempt，不手工重写 Promotion journal。
- `CONFIG_MIGRATION_REQUIRED` / `EXECUTION_MIGRATION_REQUIRED`：旧配置改为 `workspace.provider: current-directory` 后重启；旧未完成 Goal 只保留历史，不自动恢复执行。检查并取消旧 Goal，从已审查的干净主目录新建 Goal。
- 报告不可读：停止宣布完成，保留 `.xgoal/reports` 与数据库，重启让恢复协议读回；不要手工删除临时文件。

## 安全清理

先运行：

```bash
xgoal clean --dry-run
xgoal clean
```

当前只清理已取消 Goal 下、没有 EnvironmentSnapshot/Validator/FinalReport 引用的当前目录会话元数据；保留当前源码、旧 worktree 和服务诊断日志。不要手工删除 `.xgoal/state.db*`、`packets/`、`patches/`、`promotions/` 或 `reports/`；需要恢复旧数据库时先停止 Daemon，并使用已验证的 `backups/` 副本做受控恢复。

## 不自动执行的动作

xgoal v0.1 不自动 merge/rebase 用户分支、push、创建 PR、发布制品、操作生产、上传 Benchmark 或删除审计历史。这些动作需要独立授权和项目外发布流程。
