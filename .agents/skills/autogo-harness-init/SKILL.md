# autogo-harness-init
## 目标
在外部安装器已放入完整通用 Harness 与 docs 工作区骨架后，由原生 Agent 理解真实项目并按需初始化项目特有事实入口、语义组件规则和真实任务状态。
## 输入与发现
- 项目 README、目录、构建文件、测试、部署和当前用户目标
- 已安装根项目指令、Skills 和模板
- 已有项目文档与本地约束

## 输出与持久制品
- 按需更新根 `AGENTS.md` 中项目自有的事实上下文（可参考 `.autogo/templates/project/project-context.md`）
- 项目事实地图和实际命令入口
- 仅必要的组件 `AGENTS.md`
- 当前任务需要的具体 docs 制品与索引更新
- 当前真实目标对应的最小 `PROGRESS.md`，包含一个 Objective 及完成它所需的 Plans

## 副作用与 Human Gate
可创建项目治理和 docs 文件；不得改业务代码、部署或数据。

## 执行步骤
1. 定位项目根后，先读取并对账安装时初始化的全局唯一 `PROGRESS.md`，为当前真实目标登记 Objective → Plans；不预建未来占位任务
2. 再读项目事实，不扫描后机械生成文件
3. 阅读完整参考样例并结合真实项目事实，更新根项目指令的项目自有上下文；不要复制样例事实或改写安装器托管治理区块
4. 识别独立语义组件及其特殊约束
5. 只有存在真实增量规则时才创建局部项目指令
6. 复用已初始化的 docs 工作区，只创建当前任务真正需要的具体制品并更新索引
7. 不创建根 ./harness、Runtime、Work CRUD 或重复任务状态文件
8. 用当前项目的构建、测试或文档入口验证本次初始化结果；不检查 Harness 自身的安装内容或固定文案
9. 在对应制品中记录初始化假设、当前 Plan 的内部下一步和仍需用户确认的项目语义

## 验证与完成
- 重复执行幂等且不复制父规则
- 没有占位任务或虚构项目事实
- 新建组件规则与真实边界对应
- 当前工作可从 Progress 恢复到 Objective 和当前 Plan
- 用户无需学习任何 Harness 命令

## 失败、重试与幂等
无法确定组件边界时保持继承根规则，不臆造局部约束。
- 重复执行前读取当前文件、Git 和运行状态；不重复创建已存在制品或重复执行已生效副作用。
- 相同失败再次出现时停止机械重试，回到 `autogo-investigate` 或上层设计。
- 状态和文档由 Agent 自动维护，不要求用户执行 Harness CRUD 命令。
