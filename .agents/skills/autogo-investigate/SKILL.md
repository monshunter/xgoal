# autogo-investigate
## 目标
在修改前建立可复核的问题模型、系统事实、根因候选和验证路径，避免凭症状或记忆直接编码。
## 输入与发现
- 独立只读调查的用户问题，或 Standard Objective / 正式 Plan 中的调查 Item
- 用户现象、日志、错误、相关代码和历史变更
- 规范事实与实际运行状态
- 可安全执行的只读或低副作用检查

## 输出与持久制品
- 已确认事实、假设、排除项和不确定性
- 根因或按概率排序的候选根因
- 最小复现、影响范围和建议下一步
- 需要补充的 Spec/Design/Plan 或 Human Gate
- 独立只读调查的对话结论，或写入对应事实 owner 的调查结论、等待条件和下一 Skill

## 副作用与 Human Gate
默认只读。独立 Diagnose-only 或未授权调查不得修改项目；为已授权变更复现而执行的环境操作必须可逆并遵守 autogo-env-manage 约束。

## 执行步骤
1. 确认调用模式：独立只读调查直接锁定用户问题；Standard 调查从 Progress、正式 Plan、相关 Spec 或 Review 锁定当前 Item
2. 明确问题边界和成功判据
3. 建立从入口到失败点的数据流、状态和依赖图
4. 优先复现；不能复现时收集最小证据
5. 用对照实验逐个排除候选，不同时改变多个变量
6. 定位根因后评估影响、风险、修复和回归验证
7. 独立只读调查只在对话交付发现；Standard 将事实、Evidence 和下一步写入对应事实 owner，Plan 只更新任务是否完成
8. 调查发现修复机会时检查是否已有写入授权；没有则交付发现，有授权且属于当前 Objective 时返回 Reconcile 或对应写入 Skill，独立新结果则重新 Intake

## 验证与完成
- 结论能指向代码、日志、命令或实验
- 事实与推断明确分离
- 复现或无法复现的条件被记录
- 建议修复针对根因而非仅症状
- 当前内部调查项的状态和下一步已与 Evidence 对账

## 失败、重试与幂等
证据互相冲突时保留冲突并设计新的辨别实验；无法安全复现时说明不确定性和恢复条件，不猜测。
- 重复执行前读取当前文件、Git 和运行状态；不重复创建已存在制品或重复执行已生效副作用。
- 相同失败再次出现时停止机械重试，回到 `autogo-investigate` 或上层设计。
- 状态和文档由 Agent 自动维护，不要求用户执行 Harness CRUD 命令。
