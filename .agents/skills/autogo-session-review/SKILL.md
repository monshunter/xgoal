# autogo-session-review
## 目标
在确有改进价值时复盘决策、摩擦和恢复过程，优先发现可以删除、合并或自动化的负担；不把复盘变成每次交付的固定仪式。

## 输入与发现
- 本次目标、实际路径、Diff、失败、恢复和用户反馈
- 相关 Review、Bug、Operation 或运行 Evidence
- 触发复盘的重复模式、复杂度或明确用户要求

## 输出与持久制品
- 有效做法、问题、根因候选和最小改进建议
- 有充分复用价值时的 `EVO-*` 文档与 Index；否则只返回口头结论

## 副作用与 Human Gate
可以修改复盘/演进文档；默认不修改项目指令、Skill 或工作流。修改用户个人全局 Harness 需要 Human Gate。

## 执行步骤
1. 说明触发本次复盘的具体信号，不因 Standard、Close 或 Commit 自动开始
2. 比较预期路径与实际路径，区分产品、项目、工具、Skill 和偶发问题
3. 用当前 Evidence 识别根因与重复成本，优先提出删除、合并或自动化
4. 产品、测试或恢复缺陷返回对应 owner Reconcile，不把它包装成 Harness 演进
5. 只有存在可复用问题、明确收益和可验证改进时创建或更新唯一 `EVO-*` 并同步 Index
6. 证据不足或没有可复用价值时直接结束，不创建空文档，也不阻塞当前交付

## 验证与完成
- 复盘由具体触发信号和 Evidence 支撑
- 建议说明收益、成本、风险与适用范围
- 没有因单次偶发问题膨胀根治理
- 没有把 Session Review 作为 Plan、Journal 或 Commit 的固定前置条件

## 失败、重试与幂等
证据不足时停止，不强行产出 Evolution；重复执行前读取现有记录并更新同一问题 owner。
