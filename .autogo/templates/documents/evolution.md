# EVO-001：从变量模板演进为完整参考样例

> 这是 Harness 演进提案样例。它展示提案应如何引用事实、说明风险和验证回放，不代表自动获得实施授权。

状态：proposal

## 证据与出现次数

- 16 份模板中存在 YAML Front Matter 或占位变量。
- 多份中文模板包含整段英文标题。
- 生命周期校验器通过搜索机器字段判断模板是否有效。

## 根因

模板的 owner 不清晰：内容按脚本输入设计，实际却由 Agent 阅读。结果是既没有真正的渲染入口，也没有足够完整的参考内容。

## 提案

将全部模板改为固定路径的完整中文样例，删除文档 Front Matter 和插值变量。机器校验只验证固定文件、关键语义结构和资源完整性。

## 受影响的规则、Skill 与模板

- docs 文档契约与根生命周期说明；
- `autogo-plan-write`、`autogo-spec-write`、`autogo-doc-index`；
- `.autogo/templates/` 下的全部参考文件；
- 资源清单、安装测试和 acceptance。

## 风险与批准

主要风险是旧工具仍期待 Front Matter 字段。实施前必须搜索所有读取方，并把仍有业务价值的关系迁移到正文。任何外部消费者无法确认时，应停止删除对应契约。

## 复杂度变化

删除变量字典、渲染假设和双语空壳；新增成本仅为维护有意义的样例内容。整体概念和运行依赖减少。

## 验证与历史回放

- 对旧安装 Manifest 执行更新，确认可安全退休旧模板路径。
- 对全新 Codex 和 Claude Code 项目执行安装。
- 运行现有资源包、安装器和结构校验测试。

## 回滚

如果发现必须依赖结构化字段的当前消费者，恢复上一版资源路径和校验规则，同时保留本次审计证据，重新设计最小机器契约。
