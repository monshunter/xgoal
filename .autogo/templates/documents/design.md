# DESIGN-001：可直接阅读的 Harness 参考资料设计

> 这是完整设计文档样例。真实设计应保留相同的问题覆盖面，但内容必须来自当前项目证据。

## 上下文与目标

`.autogo/templates/` 的直接使用者是 Agent。目标是让 Agent 只阅读一份文件，就能理解该类文档的内容深度、边界和证据表达方式。

## 已知事实与假设

- 安装器能够原样分发静态文件，不需要模板渲染器。
- Agent 可以根据完整样例和当前项目事实创建新文档。
- Host Adapter 仍负责安装路径映射，但不参与参考文件内容编排。

## 方案与权衡

采用“固定文件名 + 完整中文样例”。这会放弃脚本批量填空的便利，但减少渲染协议、变量字典和空壳文档三类复杂度。

## 组件和职责

| 组件 | 职责 |
|---|---|
| `harness/locales/zh-CN/templates/` | 保存可直接阅读的中文参考样例 |
| `harness/pack.json` | 声明固定资源路径、类型和权限 |
| 安装器 | 原样分发资源并维护安装生命周期 |
| Agent Skill | 读取样例和项目事实，创建真实文档 |

## 契约、数据与状态

参考文件不定义运行时数据模型。根 `PROGRESS.md` 只维护 Objective 三态和内嵌 Plans Checklist；正式 Plan 只维护 Phase Checklist，Spec 负责行为与验收定义。

## 失败与恢复

- 资源包结构无效时，安装器在写入前拒绝安装。
- AutoGo 管理文件按当前资源覆盖；安装后验证失败时事务回滚。
- 内容审查失败时只修正对应样例，不引入新的生成层。

## 安全、观测与成本

样例不得包含凭证、真实用户数据或无法验证的生产信息。验证输出应报告具体文件和缺失结构，避免只给出笼统 PASS。

## 迁移、部署与回滚

旧 `.tmpl` 路径作为历史托管资源安全退休；新资源安装到固定路径。回滚时可恢复上一版本资源包和 Manifest，不修改项目自有文档。

## 验证计划

1. 校验资源包路径、登记关系和文件数量。
2. 检查模板目录无 Front Matter、占位符和 `.tmpl` 后缀。
3. 运行 Go 单元测试和安装器定向测试。
4. 从 `temp/` 完成 Codex、Claude Code 与共存安装验收。
