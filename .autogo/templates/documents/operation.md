# OP-001：更新项目中的 AutoGo Harness 资源

> 这是操作文档样例。真实执行前必须重新确认目标目录、版本、权限和回滚点。

## 目标环境与范围

目标是一个已安装 AutoGo Harness 的本地项目。操作只更新 AutoGo 管理的 Skill、工作流和参考资料，不修改业务代码或项目自有文档。

## 执行前检查

1. 确认当前目录是目标项目根目录。
2. 检查 Git 工作区，识别本地未提交修改的 owner。
3. 记录当前 `autogo` 版本和 `.autogo/manifests/` 内容。
4. 确认新资源包完整且摘要校验通过。

## 差异预览

先运行 dry-run，检查将新增、更新、退休和保留的路径。若出现业务文件或未知路径，停止执行并调查 Manifest 归属。

## 恢复方案

安装器使用事务快照回滚本轮失败。执行前另记录当前版本号；如更新后行为异常，重新安装上一已知可用版本，并保留冲突报告供诊断。

## 人工确认点

默认本地更新无需额外确认。若操作将覆盖本地修改、改变公共接口或触发不可逆外部影响，必须先获得用户明确授权。

## 执行

运行目标版本的 `autogo`。不要手工删除 `.autogo/` 或 Agent 原生 Skill 目录，也不要用 `git reset` 清理项目改动。

## 健康检查与观察

- 根治理区块只出现一次；
- Agent 原生目录只包含 `skills/`；
- `.autogo/templates/` 中参考文件可直接阅读；
- 严格结构校验输出 `0 errors, 0 warnings`；
- 重复安装不产生额外差异。

## 证据记录

记录命令、退出码、关键输出、安装 Manifest 摘要和最终 Git 状态。未运行的检查不得记为通过。
